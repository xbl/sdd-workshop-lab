# 限额活动报名练习 · 项目原则

## 先确认规格

用业务目标、规则、异常和可观察的验收用例写清需要支持的行为。有疑问时向讲师确认，并把答复写进规格。学员评审确认 `spec.md` 后再做技术方案和任务拆分。计划和任务应能追溯到已确认的规则。

## 严格边界与模拟数据库约束（架构红线）

本项目为轻量级纯前端与纯逻辑练习，**严禁 AI 引入任何不必要的外部系统与复杂性**：

1. **严禁引入任何真实数据库**：严禁创建、安装或建议使用 SQLite、MySQL、PostgreSQL、IndexedDB、Redis 等任何真实数据库。
2. **严禁引入后端服务或外部依赖**：严禁引入 Express、Fastify、Next.js 等后端框架，严禁引入任何第三方 npm 依赖包（项目必须保持 0 外部依赖）。
3. **模拟数据库契约**：
   - 唯一的“数据库”即为纯内存对象 `state`：
     - `state.capacity`: 名额上限（数字）
     - `state.startsAt`: 开始时间戳（毫秒数）
     - `state.registrations`: 报名记录列表 `Array<{ userId: string, registrationId: string }>`
   - 数据的“查询”与“写入”全部通过纯函数操作 `state` 完成，返回更新后的新 `state` 对象。
4. **代码修改范围限制**：
   - 实现代码仅限于 `registration.js`，严格保持 `register(state, { userId, now })` 的纯函数签名。
   - 严禁修改或破坏 `index.html` 与 `page.js` 的既有契约。

## 让验证可复现

运行行为测试时由调用方传入固定的 `now`，使用 Node.js 自带的测试工具即可（`node --test`）。任务写清被验的规则、操作和可观察的结果。保留规格、任务和实际执行状态，供课堂回看。
